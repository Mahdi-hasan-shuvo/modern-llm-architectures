LLM কী? — পুরো ছবিটা বুঝে নেওয়া

কোড লেখার আগে ভিত্তিটা পরিষ্কার হওয়া দরকার। এই অধ্যায়ে আমরা জানব LLM আসলে কী, AI থেকে শুরু করে কীভাবে আজকের ChatGPT/Claude/Gemini-তে এসে পৌঁছালাম, এবং Token, Context Window, Embedding-এর মতো মৌলিক শব্দগুলোর মানে।

LLM আসলে কী?

Large Language Model (LLM) হলো একটি বিশাল neural network যাকে ইন্টারনেট-স্কেল টেক্সট ডেটা দিয়ে এমনভাবে প্রশিক্ষণ দেওয়া হয়েছে যাতে এটি "পরবর্তী শব্দটি (token) কী হবে" তা ভবিষ্যদ্বাণী করতে পারে। শুনতে সহজ মনে হলেও — কোটি কোটি বাক্যে এই একটি কাজ বারবার করতে করতে মডেলটি ভাষা, যুক্তি, কোড, এমনকি কিছু "common sense"-ও শিখে ফেলে।

একদম সহজ ভাষায়: LLM হলো একটি অসম্ভব শক্তিশালী autocomplete ইঞ্জিন। আপনার মোবাইল কীবোর্ডের next-word suggestion যেমন কাজ করে, LLM তার এক বিলিয়ন গুণ পরিশীলিত রূপ। পার্থক্য হলো — কীবোর্ড দেখে শেষ ২-৩টি শব্দ, আর LLM দেখে হাজার হাজার শব্দের প্রেক্ষাপট এবং প্রতিটি সিদ্ধান্তে ব্যবহার করে বিলিয়ন প্যারামিটার।

💡মূল অন্তর্দৃষ্টি

LLM "চিন্তা" করে না, "জানে" না — এটি probability distribution হিসাব করে: "এই প্রেক্ষাপটের পর কোন token-এর আসার সম্ভাবনা কত?"। বুদ্ধিমত্তার মতো যা দেখায়, তা আসলে বিশাল স্কেলে next-token prediction-এর emergent ফলাফল।

ML

নিয়ম না লিখে, ডেটা দেখিয়ে মডেলকে নিজে প্যাটার্ন শিখতে দেওয়া।

TF
Transformer

২০১৭-র "Attention Is All You Need" পেপার — আধুনিক সব LLM-এর ভিত্তি।

২০১৭ সালের আগে ভাষা মডেলে ব্যবহৃত হতো RNN ও LSTM, যা শব্দ একটার পর একটা ক্রমে পড়ত — ফলে ধীর এবং দীর্ঘ প্রেক্ষাপট মনে রাখতে অক্ষম। Transformer এই সমস্যা ভাঙল self-attention দিয়ে: একসাথে পুরো বাক্যের সব শব্দ পরস্পরের দিকে "তাকাতে" পারে, এবং পুরোটা সমান্তরালে (parallel) প্রসেস হয় — তাই GPU-তে দ্রুত ট্রেনিং সম্ভব হলো।

GPT, Claude, Gemini, Llama — কীভাবে কাজ করে

এই চারটি মডেলই মূলত একই Transformer ভিত্তির উপর দাঁড়িয়ে, কিন্তু ভিন্ন ভিন্ন প্রতিষ্ঠান, ডেটা ও কৌশলে প্রশিক্ষিত। সবগুলোই decoder-only autoregressive মডেল — অর্থাৎ একটার পর একটা token তৈরি করে এগোয়।

Token কী?

LLM সরাসরি অক্ষর বা শব্দ পড়ে না — এটি পড়ে token, যা শব্দের ছোট ছোট টুকরা। ইংরেজিতে গড়ে ১ token ≈ ০.৭৫ শব্দ বা ~৪ অক্ষর। যেমন "unbelievable" ভেঙে যেতে পারে ["un", "believ", "able"]-এ।

Text → Tokens 
  "I love machine learning"
        │  (tokenizer)
        ▼
  ["I", " love", " machine", " learning"]
        │  (vocabulary lookup)
        ▼
  [40,  1842,    5662,        4673]   ← token IDs (সংখ্যা)

মডেলের কাছে token মানেই হলো এই সংখ্যাগুলো (IDs)। কেন টোকেন গুরুত্বপূর্ণ? কারণ — API-র দাম token-এ হিসাব হয়, context window-এর সীমা token-এ মাপা হয়, এবং মডেলের গতিও token/সেকেন্ডে।

Context Window কী?

Context window হলো একসাথে কত token মডেল "মনে রাখতে" বা একবারে দেখতে পারে তার সর্বোচ্চ সীমা — এতে আপনার prompt, ইতিহাস, এবং মডেলের উত্তর সবই থাকে। GPT-2-তে ছিল মাত্র ১,০২৪ token; ২০২৬-এর আধুনিক মডেলে তা ১২৮K থেকে ১M+ পর্যন্ত।

📏উপমা

Context window-কে ভাবুন মডেলের working memory হিসেবে — একটা ডেস্কের উপর যত কাগজ একসাথে রাখা যায়। ডেস্ক ভরে গেলে পুরোনো কাগজ সরাতে হয় (truncation), আর মডেল তখন শুরুর তথ্য "ভুলে" যায়।

Embedding কী?

Token ID শুধু একটা সংখ্যা — এর কোনো "অর্থ" নেই। Embedding হলো প্রতিটি token-কে একটি বহু-মাত্রিক vector-এ (যেমন ৭৬৮ বা ৪০৯৬ সংখ্যার তালিকা) রূপান্তর, যেখানে অর্থে কাছাকাছি শব্দ vector-স্পেসে কাছাকাছি অবস্থান করে।

"রাজা" − "পুরুষ" + "নারী" ≈ "রানী"
Embedding স্পেসে অর্থের সম্পর্ক জ্যামিতিক দূরত্ব হিসেবে ধরা পড়ে

অর্থাৎ embedding হলো ভাষাকে সংখ্যার জগতে অনুবাদ করা, যাতে neural network গণিত করতে পারে। অধ্যায় ৫-এ আমরা embedding নিয়ে গভীরে যাব।

Transformer Architecture — গভীরে

এটিই পুরো গাইডের হৃদয়। Encoder, Decoder, Self-Attention, Multi-Head Attention, Positional Encoding, Feed-Forward, Residual Connection ও Layer Normalization — প্রতিটি অংশ কেন আছে এবং কীভাবে একসাথে কাজ করে, ছবি ও গণিতসহ বুঝব।

Encoder vs Decoder

E
Encoder

পুরো ইনপুট একবারে পড়ে এর একটি অর্থপূর্ণ উপস্থাপন (representation) তৈরি করে। প্রতিটি token সব token দেখতে পায় (bidirectional)। উদাহরণ: BERT।

D
Decoder

একটার পর একটা token তৈরি করে; ভবিষ্যৎ token দেখতে পায় না (masked)। আধুনিক GPT/Claude/Llama সব decoder-only।

🎯২০২৬-এ বাস্তবতা

মূল ২০১৭ পেপারে দুটোই (অনুবাদের জন্য) ছিল। কিন্তু আজকের জনপ্রিয় চ্যাট-LLM প্রায় সবই decoder-only — সরল, scalable, এবং generation-এ চমৎকার। তাই বাকি গাইডে আমরা decoder-only-তেই ফোকাস করব।

Self-Attention — মূল জাদু

"each word looks at every other word"

একটি বাক্যে প্রতিটি শব্দের অর্থ অন্য শব্দের উপর নির্ভর করে। "ব্যাংকের পাশে নদীর তীরে বসলাম" — এখানে "ব্যাংক" মানে আর্থিক প্রতিষ্ঠান নয়, নদীর তীর; কারণ "নদী" শব্দটি প্রসঙ্গ বদলে দিয়েছে। Self-attention প্রতিটি token-কে অন্য সব token-এর দিকে "তাকিয়ে" সিদ্ধান্ত নিতে দেয় — কাকে কতটা গুরুত্ব দেব।

প্রতিটি token থেকে তিনটি vector তৈরি হয়:

Q
Query

"আমি কী খুঁজছি?" — বর্তমান token-এর প্রশ্ন।

K
Key

"আমার কাছে কী আছে?" — প্রতিটি token-এর পরিচয়/লেবেল।

V
Value

"আমি কী তথ্য বহন করি?" — আসল বিষয়বস্তু।

Attention Formula

Attention(Q,K,V) = softmax( QKT / √dk ) V
Query ও Key-এর মিল মাপো → স্কেল করো → softmax দিয়ে ওজন → Value-র ওজনিত যোগফল

ধাপে ধাপে এই সূত্রটি পড়ি:

  1. QKᵀ — প্রতিটি Query কত মেলে প্রতিটি Key-এর সাথে (similarity score / dot product)।
  2. ÷ √dₖ — মাত্রা (dimension) বড় হলে score-ও বড় হয়ে যায়; √dₖ দিয়ে ভাগ করে স্থিতিশীল রাখা হয় (নাহলে softmax খুব ধারালো হয়ে gradient মরে যায়)।
  3. softmax — score-গুলোকে ০–১ এর সম্ভাবনায় রূপান্তর (যোগফল ১), অর্থাৎ "attention weights"।
  4. × V — এই weights দিয়ে Value-গুলোর ওজনিত গড় = প্রতিটি token-এর নতুন, প্রসঙ্গ-সমৃদ্ধ উপস্থাপন।

Self-Attention — PyTorch-এ একদম স্ক্র্যাচ থেকে

self_attention.pypython
import torch
import torch.nn.functional as F

def self_attention(x, W_q, W_k, W_v):
    """
    x: (seq_len, d_model) — ইনপুট embeddings
    W_q, W_k, W_v: (d_model, d_k) — শেখা projection matrices
    """
    Q = x @ W_q          # (seq_len, d_k)  -> "আমি কী খুঁজছি"
    K = x @ W_k          # (seq_len, d_k)  -> "আমার পরিচয়"
    V = x @ W_v          # (seq_len, d_k)  -> "আমার তথ্য"

    d_k = Q.size(-1)
    # ধাপ ১: similarity scores  (QKᵀ)
    scores = Q @ K.transpose(-2, -1)          # (seq_len, seq_len)
    # ধাপ ২: scale  (÷ √d_k)
    scores = scores / (d_k ** 0.5)
    # ধাপ ৩: softmax -> attention weights
    weights = F.softmax(scores, dim=-1)       # প্রতিটি সারির যোগফল = 1
    # ধাপ ৪: weighted sum of values
    output = weights @ V                       # (seq_len, d_k)
    return output, weights

# উদাহরণ
torch.manual_seed(0)
seq_len, d_model, d_k = 4, 8, 8
x = torch.randn(seq_len, d_model)
W_q, W_k, W_v = (torch.randn(d_model, d_k) for _ in range(3))
out, attn = self_attention(x, W_q, W_k, W_v)
print("output shape:", out.shape)      # (4, 8)
print("attention weights:\n", attn.round(decimals=2))

Multi-Head Attention

একটি attention "মাথা" (head) একধরনের সম্পর্ক ধরে। কিন্তু ভাষায় একসাথে অনেক ধরনের সম্পর্ক থাকে — কোনটা ব্যাকরণগত, কোনটা অর্থগত, কোনটা দূরত্বের। তাই আমরা একাধিক head সমান্তরালে চালাই; প্রতিটি ভিন্ন "দৃষ্টিকোণ" শেখে, তারপর সবগুলো একত্র (concatenate) করে আবার project করা হয়।

            │
   ┌────────┼────────┬────────┐
   ▼        ▼        ▼        ▼
 Head 1   Head 2   Head 3 ... Head h     ← প্রতিটি আলাদা Q,K,V
 (syntax) (corref) (distance)            ← ভিন্ন সম্পর্ক শেখে
   │        │        │        │
   └────────┴───┬────┴────────┘
            Concat
              │
          Linear (W_o)
              │
            Output
multi_head_attention.pypython
import torch
import torch.nn as nn

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        assert d_model % n_heads == 0
        self.d_k = d_model // n_heads
        self.n_heads = n_heads
        self.qkv = nn.Linear(d_model, d_model * 3)   # Q,K,V একসাথে
        self.out = nn.Linear(d_model, d_model)

    def forward(self, x, mask=None):
        B, T, C = x.shape                       # batch, seq_len, d_model
        qkv = self.qkv(x).chunk(3, dim=-1)      # 3 × (B, T, C)
        q, k, v = [t.view(B, T, self.n_heads, self.d_k).transpose(1, 2)
                   for t in qkv]                # (B, heads, T, d_k)

        att = (q @ k.transpose(-2, -1)) / (self.d_k ** 0.5)
        if mask is not None:                    # causal mask (decoder)
            att = att.masked_fill(mask == 0, float('-inf'))
        att = att.softmax(dim=-1)
        y = att @ v                             # (B, heads, T, d_k)
        y = y.transpose(1, 2).contiguous().view(B, T, C)  # concat heads
        return self.out(y)

Positional Encoding

Attention নিজে থেকে শব্দের ক্রম জানে না — তার কাছে "বিড়াল ইঁদুর খেল" আর "ইঁদুর বিড়াল খেল" একই দেখায়! তাই প্রতিটি অবস্থানে একটি অনন্য positional encoding যোগ করা হয়, যাতে মডেল ক্রম বুঝতে পারে। মূল পেপারে sine/cosine তরঙ্গ ব্যবহার হয়েছিল:

PE(pos,2i) = sin( pos / 100002i/d )
PE(pos,2i+1) = cos( pos / 100002i/d )
প্রতিটি অবস্থান পায় ভিন্ন কম্পাঙ্কের তরঙ্গের অনন্য স্বাক্ষর
🆕২০২৬ আপডেট

আধুনিক মডেল (Llama, Mistral, Qwen) এখন স্থির sin/cos-এর বদলে RoPE (Rotary Positional Embedding) ব্যবহার করে — এটি দীর্ঘ context-এ ভালো generalize করে এবং relative position আরও সুন্দরভাবে ধরে।

Feed-Forward, Residual ও Layer Norm

প্রতিটি Transformer ব্লকে attention-এর পরে আরও তিনটি অপরিহার্য অংশ থাকে:

FFN
Feed-Forward Network

প্রতিটি token-এ আলাদাভাবে দুটি linear layer + activation (GELU/SwiGLU)। এখানেই মডেলের বেশিরভাগ "জ্ঞান" parameter আকারে জমা থাকে।

+
Residual Connection

ইনপুটকে আউটপুটের সাথে যোগ (x + sublayer(x))। গভীর নেটওয়ার্কে gradient বাঁচায়, ট্রেনিং স্থিতিশীল রাখে।

LN
Layer Normalization

প্রতিটি স্তরের আউটপুট normalize করে — দ্রুত ও স্থিতিশীল ট্রেনিং। আধুনিক মডেলে RMSNorm ও pre-norm জনপ্রিয়।

transformer_block.pypython
import torch.nn as nn

class TransformerBlock(nn.Module):
    def __init__(self, d_model, n_heads, ff_mult=4, dropout=0.1):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.attn = MultiHeadAttention(d_model, n_heads)
        self.ln2 = nn.LayerNorm(d_model)
        self.ff = nn.Sequential(
            nn.Linear(d_model, ff_mult * d_model),
            nn.GELU(),
            nn.Linear(ff_mult * d_model, d_model),
            nn.Dropout(dropout),
        )

    def forward(self, x, mask=None):
        # pre-norm + residual (আধুনিক স্টাইল)
        x = x + self.attn(self.ln1(x), mask)   # Attention sublayer
        x = x + self.ff(self.ln2(x))           # Feed-forward sublayer
        return x
✓Best Practices
  • আধুনিক মডেলে pre-norm (LayerNorm আগে, sublayer পরে) ব্যবহার করুন — গভীর নেটওয়ার্কে অনেক বেশি স্থিতিশীল।
  • সম্ভব হলে RoPE + RMSNorm + SwiGLU activation — ২০২৬-এর de-facto স্ট্যান্ডার্ড।
  • লম্বা sequence-এ Flash Attention ব্যবহার করুন — একই গণিত, কিন্তু GPU মেমরি ও গতিতে বিশাল লাভ।
✕Common Mistakes
  • Scaling (÷√dₖ) বাদ দেওয়া → softmax saturate, gradient মরে যায়।
  • Decoder-এ causal mask না দেওয়া → মডেল ভবিষ্যৎ token দেখে "চিট" করে, eval-এ ধরা পড়ে।
  • Residual connection বাদ → গভীর মডেলে vanishing gradient, ট্রেনিং আটকে যায়।

একটি LLM যত ভালো, তার ডেটা তত ভালো। "Garbage in, garbage out" এখানে চরম সত্য।

  3. Dataset Preparation — নির্দিষ্ট ফরম্যাটে সাজানো, train/validation/test ভাগ, এবং shard আকারে সংরক্ষণ।
clean_dataset.pypython
import re
from datasets import load_dataset

ds = load_dataset("text", data_files={"train": "raw/*.txt"})

def is_good(example):
    text = example["text"]
    if len(text) < 200:                       # খুব ছোট বাদ
        return False
    if text.count("http") > 20:               # লিংক-স্প্যাম বাদ
        return False
    words = text.split()
    uniq_ratio = len(set(words)) / max(len(words), 1)
    return uniq_ratio > 0.3                    # পুনরাবৃত্তি বেশি হলে বাদ

def clean(example):
    t = re.sub(r"\s+", " ", example["text"]).strip()
    t = re.sub(r"\S+@\S+\.\S+", "[EMAIL]", t)  # PII mask
    return {"text": t}

ds = ds.filter(is_good).map(clean)
ds = ds["train"].train_test_split(test_size=0.01)
print(ds)

ধাপ ৪–৫ · Tokenization ও Embedding

পরিষ্কার টেক্সটকে টোকেনে ভেঙে সংখ্যা (IDs) বানানো হয় (অধ্যায় ৪), তারপর সেই IDs embedding vector-এ রূপান্তরিত হয় (অধ্যায় ৫)। এই দুটো ধাপ ছাড়া neural network কিছুই করতে পারে না — কারণ এটি কেবল সংখ্যা বোঝে।

ধাপ ৬ · Pretraining — সবচেয়ে ব্যয়বহুল অংশ

Pretraining হলো বিলিয়ন-ট্রিলিয়ন token-এর উপর মডেলকে শুধু একটাই কাজ শেখানো: next-token prediction। এখানেই কোটি কোটি ডলার ও হাজার হাজার GPU-ঘণ্টা খরচ হয়। ফলাফল একটি base model — যা ভাষা জানে, কিন্তু এখনো instruction মানতে শেখেনি।

Loss = − Σ log P( tokent | token<t )
Cross-entropy loss: সঠিক পরবর্তী token-এর সম্ভাবনা যত বাড়ে, loss তত কমে

ধাপ ৭ · Fine-Tuning

Base model-কে নির্দিষ্ট আচরণ শেখানো — যেমন প্রশ্নের উত্তর দেওয়া, instruction মানা (Instruction Tuning), বা কোনো নির্দিষ্ট ডোমেইন (মেডিকেল/আইন)। তুলনায় অনেক কম ডেটা ও খরচ। বিস্তারিত অধ্যায় ৮-এ।

ধাপ ৮ · RLHF — মানুষের পছন্দে সাজানো

RLHF (Reinforcement Learning from Human Feedback) হলো সেই গোপন উপাদান যা base model-কে সহায়ক, নিরাপদ ও বিনয়ী assistant-এ পরিণত করে।

✓Best Practices
  • মডেল scale করার আগে ডেটার মানে বিনিয়োগ করুন — quality > quantity।

  • Pretraining ভাষা শেখায় (ব্যয়বহুল); Fine-tuning + RLHF আচরণ গড়ে (সস্তা কিন্তু সিদ্ধান্তমূলক)।
  • ডেটার মানই চূড়ান্ত মান নির্ধারণ করে — pipeline-এর হৃদয় ধাপ ১–৩।

Similarity Search — কতটা মিল?

দুটো vector কতটা মেলে তা মাপা হয় সাধারণত cosine similarity দিয়ে — তাদের মধ্যবর্তী কোণের cosine। মান ১ মানে একই দিক (খুব মিল), ০ মানে সম্পর্কহীন।

cosine(A,B) = ( A · B ) / ( ‖A‖ ‖B‖ )
দুই vector-এর কোণ যত ছোট, similarity তত বেশি (১-এর কাছে)

import torch

# যেকোনো .txt ফাইল — এখানে character-level (সরলতার জন্য)
text = open("input.txt", encoding="utf-8").read()
chars = sorted(set(text))
vocab_size = len(chars)

stoi = {c: i for i, c in enumerate(chars)}   # char → id
itos = {i: c for c, i in stoi.items()}       # id → char
encode = lambda s: [stoi[c] for c in s]
decode = lambda l: "".join(itos[i] for i in l)

data = torch.tensor(encode(text), dtype=torch.long)
n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]

block_size = 128                              # context length
def get_batch(split, batch_size=32):
    d = train_data if split == "train" else val_data
    ix = torch.randint(len(d) - block_size, (batch_size,))
    x = torch.stack([d[i:i+block_size] for i in ix])
    y = torch.stack([d[i+1:i+block_size+1] for i in ix])   # shifted by 1
    return x, y

ধাপ ২ · Attention block + Transformer block

blocks.pypython
import torch, torch.nn as nn
from torch.nn import functional as F

class Head(nn.Module):
    def __init__(self, n_embd, head_size, block_size):
        super().__init__()
        self.key   = nn.Linear(n_embd, head_size, bias=False)
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)
        # causal mask: ভবিষ্যৎ token লুকানো
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B, T, C = x.shape
        k, q, v = self.key(x), self.query(x), self.value(x)
        att = q @ k.transpose(-2, -1) * C**-0.5
        att = att.masked_fill(self.tril[:T, :T] == 0, float('-inf'))
        att = F.softmax(att, dim=-1)
        return att @ v

class Block(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super().__init__()
        hs = n_embd // n_head
        self.heads = nn.ModuleList([Head(n_embd, hs, block_size) for _ in range(n_head)])
        self.proj  = nn.Linear(n_embd, n_embd)
        self.ffn   = nn.Sequential(
            nn.Linear(n_embd, 4*n_embd), nn.GELU(), nn.Linear(4*n_embd, n_embd))
        self.ln1, self.ln2 = nn.LayerNorm(n_embd), nn.LayerNorm(n_embd)

    def forward(self, x):
        h = torch.cat([head(self.ln1(x)) for head in self.heads], dim=-1)
        x = x + self.proj(h)          # residual 1
        x = x + self.ffn(self.ln2(x)) # residual 2
        return x

ধাপ ৩ · পুরো GPT মডেল

model.pypython
class MiniGPT(nn.Module):
    def __init__(self, vocab_size, n_embd=192, n_head=6, n_layer=6, block_size=128):
        super().__init__()
        self.block_size = block_size
        self.tok_emb = nn.Embedding(vocab_size, n_embd)
        self.pos_emb = nn.Embedding(block_size, n_embd)
        self.blocks  = nn.Sequential(*[Block(n_embd, n_head, block_size) for _ in range(n_layer)])
        self.ln_f    = nn.LayerNorm(n_embd)
        self.head    = nn.Linear(n_embd, vocab_size)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        tok = self.tok_emb(idx)                                  # (B,T,C)
        pos = self.pos_emb(torch.arange(T, device=idx.device))  # (T,C)
        x = self.blocks(tok + pos)
        logits = self.head(self.ln_f(x))                         # (B,T,vocab)
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, max_new_tokens):
        for _ in range(max_new_tokens):
            logits, _ = self(idx[:, -self.block_size:])
            probs = F.softmax(logits[:, -1, :], dim=-1)
            idx = torch.cat([idx, torch.multinomial(probs, 1)], dim=1)
        return idx

device = "cuda" if torch.cuda.is_available() else "cpu"
model = MiniGPT(vocab_size, block_size=block_size).to(device)
opt = torch.optim.AdamW(model.parameters(), lr=3e-4)

for step in range(5000):
    xb, yb = get_batch("train")
    xb, yb = xb.to(device), yb.to(device)
    _, loss = model(xb, yb)
    opt.zero_grad(set_to_none=True)
    loss.backward()
    opt.step()
    if step % 500 == 0:
        print(f"step {step:5d} | loss {loss.item():.4f}")

🔬এটা কেন গুরুত্বপূর্ণ

এই ~১৫০ লাইনই GPT-র সম্পূর্ণ মূল ধারণা ধারণ করে। GPT-4 আর এই Mini-GPT-র পার্থক্য মূলত scale (আরও বড় layer, head, ডেটা, compute) — architecture প্রায় একই। একবার নিজে চালালে "ব্ল্যাক বক্স" আর রহস্য থাকে না।

✓Best Practices
  • ছোট থেকে শুরু করুন (অল্প layer/embd), CPU-তেও চলবে; তারপর scale করুন।
  • AdamW + learning-rate warmup + cosine decay ব্যবহার করুন।
  • train ও val loss দুটোই ট্র্যাক করুন — val বাড়তে থাকলে overfitting।
✕Common Mistakes
  • target এক ধাপ shift করতে ভুলে যাওয়া (y = পরের token)।
  • causal mask বাদ দেওয়া → মডেল ভবিষ্যৎ দেখে, generate-এ অর্থহীন আউটপুট।
  • optimizer.zero_grad() না দেওয়া → gradient জমে যায়।
📌অধ্যায় ৬ — সারসংক্ষেপ
  • GPT = Token+Pos embedding → N× (Masked Attention + FFN) → Linear head।
  • Training = next-token prediction-এ cross-entropy loss কমানো।
  • GPT-4 আর Mini-GPT-র মূল পার্থক্য scale, ধারণা নয়।
অধ্যায় ০৭ · RAG

Retrieval-Augmented Generation (RAG)

LLM-কে আপনার নিজের ডেটা (PDF, ডকুমেন্ট, ডেটাবেস) দিয়ে "কথা বলানো"-র সবচেয়ে জনপ্রিয় কৌশল। কেন RAG দরকার, এর প্রতিটি অংশ, এবং FAISS দিয়ে একটি কাজ-করা RAG পাইপলাইন।

কেন RAG?

একটি pretrained LLM শুধু সেটুকুই জানে যা ট্রেনিংয়ের সময় দেখেছে। তিনটি বড় সমস্যা:

  • Knowledge cutoff — ট্রেনিংয়ের পরের ঘটনা জানে না।
  • Hallucination — না জানলে আত্মবিশ্বাসের সাথে ভুল বানিয়ে বলে।
  • Private data — আপনার কোম্পানির অভ্যন্তরীণ ডকুমেন্ট তো জানেই না।

RAG-এর সমাধান: প্রশ্নের সাথে সম্পর্কিত তথ্য আগে একটি knowledge base থেকে খুঁজে এনে (retrieve), সেটি prompt-এ ঢুকিয়ে (augment) তারপর LLM-কে উত্তর দিতে বলা (generate)। মডেল re-train না করেই নতুন/ব্যক্তিগত জ্ঞান পায়।

প্রতিটি অংশ

1
Chunking

বড় ডকুমেন্টকে ছোট টুকরায় (যেমন ৫০০ token, কিছুটা overlap সহ) ভাগ করা।

2
Embedding

প্রতিটি chunk-কে vector-এ রূপান্তর করে index-এ জমানো।

3
Vector DB

FAISS/Qdrant/Pinecone-এ vector সংরক্ষণ ও দ্রুত nearest-neighbour search।

4
Retrieval

query-র সাথে সবচেয়ে মিল top-k chunk বের করা।

5
Context Injection

retrieved chunk + প্রশ্ন একসাথে prompt-এ সাজানো।

6
Generation

LLM ঐ প্রসঙ্গ ধরে উত্তর দেয় — সূত্রসহ, কম hallucination।

rag_faiss.pypython
# pip install faiss-cpu sentence-transformers
import faiss, numpy as np
from sentence_transformers import SentenceTransformer

embedder = SentenceTransformer("all-MiniLM-L6-v2")

# ১) knowledge base (বাস্তবে PDF/DB থেকে chunk করে আসবে)
docs = [
    "আমাদের অফিস সকাল ৯টা থেকে বিকেল ৫টা পর্যন্ত খোলা থাকে।",
    "রিফান্ড নীতি অনুযায়ী ৭ দিনের মধ্যে ফেরত চাওয়া যায়।",
    "সাপোর্ট টিমের ইমেইল [email protected]।",
]

# ২) index তৈরি (offline)
emb = embedder.encode(docs, normalize_embeddings=True)
index = faiss.IndexFlatIP(emb.shape[1])     # inner product = cosine (normalized)
index.add(np.array(emb, dtype="float32"))

# ৩) retrieval
def retrieve(query, k=2):
    q = embedder.encode([query], normalize_embeddings=True).astype("float32")
    scores, idx = index.search(q, k)
    return [docs[i] for i in idx[0]]

# ৪) context injection + generation
def answer(query):
    context = "\n".join(f"- {c}" for c in retrieve(query))
    prompt = f"""নিচের তথ্য ব্যবহার করে বাংলায় উত্তর দাও।
তথ্য:
{context}

প্রশ্ন: {query}
উত্তর:"""
    return prompt   # এই prompt LLM-এ পাঠান (OpenAI/Ollama/vLLM)

print(answer("রিফান্ড কতদিনে পাওয়া যায়?"))
🆕২০২৬ আপগ্রেড

প্রোডাকশন RAG-এ যোগ করুন: hybrid search (keyword + vector), re-ranker (যেমন bge-reranker) দিয়ে retrieved chunk পুনরায় sort, এবং citation ফিরিয়ে দেওয়া। LangChain/LlamaIndex এসব রেডিমেড দেয়।

✓Best Practices
  • chunk size ও overlap টিউন করুন (২০০–৮০০ token, ১০–২০% overlap সাধারণ)।
  • retrieved chunk-এ সূত্র (source) রাখুন — উত্তরে citation দেখাতে পারবেন।
  • prompt-এ স্পষ্ট বলুন: "শুধু প্রদত্ত তথ্য থেকে উত্তর দাও, না জানলে বলো জানি না।"
✕Common Mistakes
  • খুব বড় chunk → অপ্রাসঙ্গিক তথ্য, context নষ্ট; খুব ছোট → প্রসঙ্গ ভেঙে যায়।
  • index ও query-তে ভিন্ন embedding মডেল।
  • retrieval মান যাচাই না করে সরাসরি প্রোডাকশন — খারাপ retrieval = খারাপ উত্তর।

F

সব parameter আপডেট। সবচেয়ে শক্তিশালী, কিন্তু বিশাল GPU/VRAM ও স্টোরেজ লাগে।

P
PEFT

Parameter-Efficient Fine-Tuning — মূল মডেল জমাট রেখে শুধু অল্প নতুন parameter শেখা। ছাতা টার্ম।

Lo
LoRA

প্রতিটি weight matrix-এর পাশে ছোট low-rank adapter যোগ করে শুধু সেটাই শেখা — ১% parameter।

Q
QLoRA

মূল মডেল 4-bit-এ quantize করে তার উপর LoRA — একটি single consumer GPU-তেই 7B–13B fine-tune সম্ভব।

LoRA — মূল weight জমাট, ছোট adapter শেখা
flowchart LR X["input"] --> W["🔒 Pretrained W
frozen, বিশাল"] X --> A["🟢 A
r×d small"] --> B["🟢 B
d×r small"] W --> SUM["＋"] B --> SUM SUM --> Y["output"]

মূল ধারণা: একটি বিশাল weight matrix W-এর পরিবর্তন ΔW-কে দুটি ছোট matrix-এর গুণফল B·A দিয়ে আনুমানিক করা যায় (low rank)। ফলে ~০.১–১% parameter শিখেই কাজ চলে — মেমরি ও খরচ নাটকীয়ভাবে কমে।

Python · 🤗 PEFT দিয়ে LoRA

lora_finetune.pypython
# pip install transformers peft datasets bitsandbytes trl
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model
import torch

model_id = "meta-llama/Llama-3.2-1B"

# QLoRA: 4-bit quantization
bnb = BitsAndBytesConfig(
    load_in_4bit=True, bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16)

tok = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id, quantization_config=bnb, device_map="auto")

# LoRA কনফিগ — শুধু attention projection-এ adapter
lora = LoraConfig(
    r=16, lora_alpha=32, lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    task_type="CAUSAL_LM")

model = get_peft_model(model, lora)
model.print_trainable_parameters()
# trainable: ~0.7%  ← বাকিটা frozen, তাই অল্প VRAM-এই চলে

from trl import SFTTrainer, SFTConfig
from datasets import load_dataset

# instruction-format ডেটা: {"text": "### প্রশ্ন:...\n### উত্তর:..."}

from fastapi import FastAPI
from pydantic import BaseModel
from openai import OpenAI

app = FastAPI()
client = OpenAI(base_url="http://localhost:8000/v1", api_key="none")  # vLLM

class Req(BaseModel):
    message: str

@app.post("/chat")
def chat(req: Req):
    resp = client.chat.completions.create(
        model="meta-llama/Llama-3.2-3B-Instruct",
        messages=[{"role": "user", "content": req.message}],
        temperature=0.7, max_tokens=512)
    return {"reply": resp.choices[0].message.content}

  7. token stream ফিরে আসে        → Backend → Frontend (SSE)
  8. পুরো কথোপকথন সংরক্ষণ          → PostgreSQL
  9. metrics লগ হয়                → Monitoring
✓Best Practices
  • Stateless backend রাখুন; state থাকুক Redis/PostgreSQL-এ → অনুভূমিকভাবে scale করা সহজ।
  • সব LLM call async + queue-এর মাধ্যমে; spike সামলাতে autoscaling।
  • সাধারণ/পুনরাবৃত্ত query cache করুন (Redis) → খরচ ও latency কমে।
  • GPU ব্যয়বহুল — utilization, কিউ-দৈর্ঘ্য, খরচ/request নিবিড়ভাবে monitor করুন।
✕Common Mistakes

  • একটিমাত্র GPU instance, কোনো failover/redundancy নেই।
  • খরচ ট্র্যাক না করা — LLM bill দ্রুত নিয়ন্ত্রণের বাইরে যেতে পারে।

অধ্যায় ১২ · Hardware & Cost

নিজের LLM তৈরিতে কী লাগবে?

GPU, VRAM, ডেটার আকার ও খরচ — বাস্তব সংখ্যা দিয়ে। ১B থেকে ৭০B পর্যন্ত মডেলে কী লাগে তার তুলনা।

VRAM-এর মোটামুটি নিয়ম

একটি সহজ আঙুলের হিসাব — শুধু inference-এর জন্য (precision অনুযায়ী):

VRAM ≈ Parameters × bytes/param × ১.২
FP16 = ২ bytes · 8-bit = ১ byte · 4-bit = ০.৫ byte (১.২ = overhead)

Training-এ লাগে আরও অনেক বেশি (~৪×) — কারণ gradient, optimizer state (Adam-এ ২×) ও activation জমা রাখতে হয়।

সম্পূর্ণ End-to-End Workflow

শেষ অধ্যায়ে সবকিছু এক সুতোয় গাঁথি। একটি User prompt কীভাবে token-by-token Final Response-এ পরিণত হয় — প্রতিটি ধাপের পেছনের Python কোডসহ।

Prompt → Final Response

প্রতিটি ধাপ — কোডে

ধাপ ১–২ · Tokenize ও Embed

from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

name = "meta-llama/Llama-3.2-1B-Instruct"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name, torch_dtype=torch.bfloat16, device_map="auto")

prompt = "বাংলায় LLM মানে কী?"
ids = tok(prompt, return_tensors="pt").to(model.device)   # ধাপ ১: tokens
# ধাপ ২: embedding লুকআপ মডেলের ভেতরেই ঘটে (input_ids → vectors)
print("token ids:", ids["input_ids"])

ধাপ ৩–৪ · Transformer Layers → Logits

with torch.no_grad():
    out = model(**ids)              # ধাপ ৩: সব transformer layer চলে
logits = out.logits[:, -1, :]      # ধাপ ৪: শেষ অবস্থানের logits (vocab-scores)
print("logits shape:", logits.shape)   # (1, vocab_size)

ধাপ ৫–৬ · Sampling → Output Token

step5_6.pypython
import torch.nn.functional as F

def sample(logits, temperature=0.8, top_p=0.9):
    logits = logits / temperature
    probs = F.softmax(logits, dim=-1)
    # top-p (nucleus): সম্ভাবনার শীর্ষ অংশ রাখো
    sp, si = torch.sort(probs, descending=True)
    cum = torch.cumsum(sp, dim=-1)
    mask = cum - sp > top_p
    sp[mask] = 0
    sp /= sp.sum(dim=-1, keepdim=True)
    nxt = si.gather(-1, torch.multinomial(sp, 1))   # ধাপ ৬: output token
    return nxt

next_id = sample(logits)
print("next token:", tok.decode(next_id[0]))
🎛️Sampling প্যারামিটার
  • temperature — কম (০.২) = নিশ্চিত/একঘেয়ে; বেশি (১.০+) = সৃজনশীল/এলোমেলো।
  • top-p / top-k — শুধু সম্ভাব্য token থেকে বাছাই করে আজেবাজে আউটপুট কমায়।

পুরো লুপ — সহজ পথ

# বাস্তবে generate() পুরো autoregressive লুপ চালায়
messages = [{"role": "user", "content": "বাংলায় LLM মানে কী?"}]

                                 add_generation_prompt=True).to(model.device)

                     top_p=0.9, do_sample=True)        # ধাপ ৭: লুপ → EOS
response = tok.decode(out[0][inputs.shape[1]:], skip_special_tokens=True)
print(response)        # 💬 Final Response
